算法基础与分析原则

从“算法是什么”到“算法好不好”：算法的定义、三条性质、三种表示，插入排序与选择排序的完整推导，以及算法分析的三条原则与渐近记号 Θ / O / Ω。所有数字与结论均取自课程 PPT《算法设计与分析》绪论（L1）。

一、算法的由来（速览）

算法不是计算机的产物，而是人类解决计算问题的古老方法；计算机只是让它跑得更快。下面这条时间线只需记住“谁、什么时候、做了什么”。

时间人物 / 典籍贡献
约公元前 300 年欧几里得《几何原本》辗转相除法：用于计算两个整数的最大公约数，被公认为最早的算法
公元前 1 世纪《周髀算经》中文“算法”一词的出处；记载勾股定理“以日下为勾，日高为股，勾股各自乘，并而开方除之”；用简便可行的方法确定天文历法、揭示日月星辰运行规律
魏晋时期刘徽《九章算术注》割圆术：用圆内接正多边形无限逼近圆，以此求取圆周率

二、算法与计算问题

计算问题 (Computational Problem)：给定数据输入，计算满足某种性质输出的问题。描述一个计算问题，必须说清楚“输入长什么样、输出要满足什么性质”。

排序是最典型的计算问题，它把“把一串数排好序”这类含糊说法，变成了可以写进论文的形式化描述：

排序问题 Sorting Problem

输入：包含 n 个数字的数组 <a1, a2, …, an>

输出：升序排列的数组 <a′1, a′2, …, a′n>，且满足 a′1 ≤ a′2 ≤ … ≤ a′n

本讲反复使用的实例（PPT 第 41 页）是一个 n = 16 的数组：

输入：<24, 17, 40, 28, 13, 14, 22, 32, 40, 21, 48, 4, 47, 8, 37, 18>

输出：<4, 8, 13, 14, 17, 18, 21, 22, 24, 28, 32, 37, 40, 40, 47, 48>

验证输出合法性只需检查链式不等式：4 ≤ 8 ≤ 13 ≤ 14 ≤ 17 ≤ 18 ≤ 21 ≤ 22 ≤ 24 ≤ 28 ≤ 32 ≤ 37 ≤ 40 ≤ 40 ≤ 47 ≤ 48。注意其中有两个 40，排序算法必须保序地保留重复元素。

三、算法的定义

算法的定义

给定计算问题，算法是一系列良定义的计算步骤，逐一执行计算步骤即可得预期的输出。

  • 良定义 (well-defined)：每一步的定义明确无歧义，执行者不需要“猜”。
  • 计算步骤：必须是计算机可实现的指令，而不是“把数据整理一下”这类人类才懂的说法。
  • “逐一执行即可得预期输出”：算法是机械的、被动的过程，不需要任何创造性。

输入 → 计算步骤 1 → 计算步骤 2 → 计算步骤 3 → … → 计算步骤 n → 输出

同一个计算问题可以对应多个算法：排序问题既有插入排序，也有选择排序，它们的输入输出规格完全相同，区别只在“怎么算”。这正是后面要比较算法效率的前提。

四、算法的性质（重点）

一个计算步骤序列要称得上算法，必须同时满足三条性质：有穷性 (Finiteness)、确定性 (Definiteness)、可行性 (Effectiveness)。PPT 对每一条都配了“反例 + 正例（选择排序）”，考试常以“判断某描述是否构成算法”的形式出现。

性质含义反例（都不构成算法）正例：选择排序
有穷性
Finiteness		 算法必须在有限个计算步骤后终止 给定输入数组，不断交换首尾元素的位置：动作序列没有终结，永远不会停 第 1 次遍历找最小元素、第 2 次在剩余数组中找次小元素、…、第 n 次找第 n 小元素，遍历次数至多与数组元素个数相同，必然终止
确定性
Definiteness		 算法必须是没有歧义的，每一个步骤都是确定的 对于给定输入数组，“交换两个数的位置”：没有具体指明是哪两个数，不同的执行者会得到不同结果 每次遍历都明确地找出最小元素并记录其位置，同一次输入下执行过程唯一
可行性
Effectiveness		 可以机械地一步一步执行基本操作步骤 “将大元素放数组后部，小元素放数组前部”：描述含糊，不可拆解为基本操作步骤 算法可一步步地执行完成：比较、赋值、交换都是基本操作

易错

三条性质各有侧重，不要混：有穷性管“会不会停”，确定性管“有没有歧义”，可行性管“能不能拆成基本操作”。反例“交换两个数的位置”是确定性不足（没指明哪两个），而不是有穷性问题；“不断交换首尾元素”才是不会终止。

五、算法的表示

算法一边要给人看（设计者），一边要给机器执行（执行者）：给人看要贴近人类思维，给机器执行要精确无歧义。这就产生了三类表示方式。

表示方式语言特点
自然语言贴近人类思维，易于理解主旨；表述不够精准，存在模糊歧义
编程语言精准表达逻辑，规避表述歧义；受限语法细节，增大理解难度
伪代码关注算法本质，便于书写阅读

以选择排序为例：自然语言说“第一次遍历找到最小元素，第二次在剩余数组中遍历找到次小元素，…，第 n 次在剩余数组中遍历找到第 n 小元素”，主旨一目了然，但“…”这种描述不严谨；用 C 或 Python 写出来又会被语法细节牵制。于是课程统一采用伪代码 (pseudocode)——它借用编程语言的书写形式作框架，却按接近自然语言的方式表达算法过程，兼顾两者优势。

伪代码书写约定

  1. 定义算法的输入和输出（如 INSERTION-SORT(A) 中 A 是输入，返回排序后的 A）。
  2. 循环语句块用缩进表示。
  3. 赋值写成 i + 1 → j（把 i + 1 赋值给 j），或等价地写成 j = i + 1。
  4. 注释使用 // 符号。
  5. 条件语句块同样用缩进表示。
  6. 不关注交换过程的实现细节（直接写 swap A[i], A[j]，不写三次赋值）。
  7. 本课程之后出现的算法均使用伪代码描述。

伪代码示例解读：快速排序的划分

划分 (PARTITION) 是快速排序的核心：它把数组重排成“左边都不大于基准、右边都不小于基准”的两段，并返回基准的最终位置。下面用 PPT 的例子数组 6 10 13 5 8 3 2 11 说明，取 p = 0、q = 7、基准 x = A[p] = 6。

伪代码

PARTITION(A, p, q)                    // 划分：以 A[p] 为基准重排 A[p..q]，返回基准位置
1  x = A[p]                           // 取区间第一个元素作为基准
2  i = p                              // i 指向「不大于基准」区间的最后一个元素
3  for j = p + 1 to q                 // j 从左到右扫描尚未处理的元素
4      if A[j] ≤ x                   // 发现一个不大于基准的元素
5          i = i + 1                   // 先把「不大于基准」区间扩大一格
6          swap A[i], A[j]             // 再把它换到该区间末尾（交换细节不展开）
7  swap A[p], A[i]                    // 最后把基准换到 i 位置，基准就此归位
8  return i                           // 返回基准的最终下标，供递归划分左右两段

C++

#include <iostream>                     // 引入输入输出流，用于打印划分结果
#include <algorithm>                    // 引入 std::swap，用于交换两个元素

int partition(int A[], int p, int q) {  // 划分函数：以 A[p] 为基准重排 A[p..q]
    int x = A[p];                       // 取区间第一个元素作为基准
    int i = p;                          // i 指向「不大于基准」区间的最后一个元素
    for (int j = p + 1; j <= q; ++j) {  // j 从左到右扫描尚未处理的元素
        if (A[j] <= x) {                // 发现一个不大于基准的元素
            ++i;                        // 先把「不大于基准」区间扩大一格
            std::swap(A[i], A[j]);      // 再把它换到该区间末尾
        }                               // if 结束
    }                                   // for 结束
    std::swap(A[p], A[i]);              // 最后把基准换到 i 位置，基准就此归位
    return i;                           // 返回基准的最终下标
}                                       // partition 结束

int main() {                                                // 用 PPT 的例子数组验证划分
    int A[8] = {6, 10, 13, 5, 8, 3, 2, 11};                 // 待划分数组
    int k = partition(A, 0, 7);                             // 对整个区间做一次划分
    std::cout << "return " << k << ": ";               // 打印返回值（基准最终位置）
    for (int t = 0; t < 8; ++t) {                           // 逐个打印划分后的元素
        std::cout << A[t] << (t == 7 ? '\n' : ' ');        // 元素间空格分隔，末尾换行
    }                                                       // for 结束
    return 0;                                               // 正常结束：输出 2 5 3 6 8 13 10 11
}                                                           // main 结束

运行结果：return 3: 2 5 3 6 8 13 10 11。基准 6 落在下标 3，左侧 2 5 3 全部 ≤ 6，右侧 8 13 10 11 全部 ≥ 6。

划分过程演示：6 10 13 5 8 3 2 11，基准 x = A[p] = 6

考点

伪代码的三条优势（关注本质、便于书写阅读、精确无歧义）与书写约定（输入输出、缩进表示语句块、i+1 → j 式赋值、// 注释、不纠缠交换细节）是本节的必背内容；三种表示方式的对比表常以选择题出现。

六、插入排序 Insertion Sort

算法思想

将数组待排序元素依次插入到已排序部分，使已排序部分保持升序的性质。具体做法是：把 A[1] 单独看作长度为 1 的已排序区间，然后 j = 2, 3, …, n 逐个把 A[j] 插入左边合适的位置——插入前先取出 key = A[j]，再用 i 从 j − 1 向左扫描，把比 key 大的元素统统后移一位，最后把 key 放进腾出来的空位 A[i + 1]。

伪代码（下标从 1 开始，忠实于 PPT 写法）

INSERTION-SORT(A)                     // 插入排序：把数组 A 就地升序排列
1  for j = 2 to A.length              // 从第 2 个元素开始，逐个把 A[j] 插入左边已排序区间
2      key = A[j]                     // 取出本轮待插入的关键字 A[j]
3      i = j - 1                      // 从 key 左边一个位置开始向左扫描
4      while i > 0 and A[i] > key    // 只要左边还有元素且它比 key 大，就继续找插入位置
5          A[i + 1] = A[i]             // 把 A[i] 后移一位，为 key 腾出空位
6          i = i - 1                   // 指针左移，继续考察前一个元素
7      A[i + 1] = key                  // 循环结束后把 key 写入正确位置 A[i + 1]

C++（0 起下标，可直接编译运行）

#include <iostream>                    // 引入输入输出流，用于打印排序结果

void insertionSort(int A[], int n) {    // 插入排序：把数组 A 的前 n 个元素就地升序排序
    for (int j = 1; j < n; ++j) {       // 对应伪代码 for j = 2 to n，0 起下标从 1 开始
        int key = A[j];                 // 取出本轮待插入的关键字 A[j]
        int i = j - 1;                  // 从 key 左边一个位置开始向左扫描
        while (i >= 0 && A[i] > key) {  // 只要左边还有元素且它比 key 大，就继续找插入位置
            A[i + 1] = A[i];            // 把 A[i] 后移一位，为 key 腾出空位
            --i;                        // 指针左移，继续考察前一个元素
        }                               // while 结束：i = -1 或 A[i] <= key
        A[i + 1] = key;                 // 把 key 写入正确位置 A[i + 1]
    }                                   // for 结束：前 j + 1 个元素已有序
}                                       // insertionSort 结束

int main() {                                                              // 用 PPT 的 16 元素实例验证
    int A[16] = {24, 17, 40, 28, 13, 14, 22, 32, 40, 21, 48, 4, 47, 8, 37, 18};  // PPT 第 41 页的输入数组
    insertionSort(A, 16);                                                 // n = 16，就地排序
    for (int k = 0; k < 16; ++k) {                                        // 逐个打印排序后的元素
        std::cout << A[k] << (k == 15 ? '\n' : ' ');                     // 空格分隔，末尾换行
    }                                                                     // for 结束
    return 0;                                                             // 输出 4 8 13 14 17 18 21 22 24 28 32 37 40 40 47 48
}                                                                         // main 结束

运行结果与 PPT 输出完全一致：4 8 13 14 17 18 21 22 24 28 32 37 40 40 47 48。

复杂度分析（最坏情况逐行计数）

设每个基本操作代价为 1，把每行伪代码的执行次数数出来（详见第九节）：

输入情况实例特征元素比较次数
最好情况数组已升序，每次只比较一次就停下1 + 1 + 1 + … + 1 = n − 1 次
最坏情况数组已降序，第 j 轮要一路比较到最左边1 + 2 + 3 + … + (n − 1) = n(n − 1)/2 次

T(n) = 3n2/2 + 7n/2 − 4 = Θ(n2)

图 1 插入排序在 n = 16 时最好情况与最坏情况的比较次数对比：最好 1 + 1 + … + 1 = n − 1 = 15 次；最坏 1 + 2 + … + (n − 1) = n(n − 1)/2 = 120 次

考点

插入排序的最坏情况是比较次数 n(n − 1)/2，最好情况是 n − 1；把它所有行的代价加起来，得到 T(n) = 3n2/2 + 7n/2 − 4 = Θ(n2)。三个数字要分清：比较次数 ≠ 总操作次数。

七、选择排序 Selection Sort

算法思想

第 1 次遍历找到最小元素，第 2 次在剩余数组中遍历找到次小元素，…，第 n 次在剩余数组中遍历找到第 n 小元素。换句话说：每一轮把未排序区间 A[i..n] 中的最小值换到 A[i]，一共做 n − 1 轮，A[i] 及其左边自然成为已排序区间。

伪代码（下标从 1 开始，忠实于 PPT 写法）

SELECTION-SORT(A)                     // 选择排序：每轮从未排序区间选出最小值放到左端
1  for i = 1 to A.length - 1          // 枚举已排序区间的右边界 i，共 n - 1 轮
2      cur_min = A[i]                  // 先假定本轮最小值是未排序区间的第一个元素
3      cur_min_pos = i                 // 记录当前最小值所在的位置
4      for j = i + 1 to A.length       // 从 i + 1 开始扫描剩余未排序元素
5          if A[j] < cur_min           // 发现一个比当前最小值更小的元素
6              cur_min = A[j]          // 更新当前最小值
7              cur_min_pos = j         // 同时更新最小值所在的位置
8      swap A[i], A[cur_min_pos]       // 把本轮最小值换到 A[i]，A[i] 就此归位

C++（0 起下标，可直接编译运行）

#include <iostream>                      // 引入输入输出流，用于打印排序结果
#include <algorithm>                     // 引入 std::swap，用于交换两个元素

void selectionSort(int A[], int n) {      // 选择排序：把数组 A 的前 n 个元素就地升序排序
    for (int i = 0; i < n - 1; ++i) {     // 对应伪代码 for i = 1 to n - 1
        int curMin = A[i];                // 先假定本轮最小值是未排序区间的第一个元素
        int curMinPos = i;                // 记录当前最小值所在的位置
        for (int j = i + 1; j < n; ++j) { // 从 i + 1 开始扫描剩余未排序元素
            if (A[j] < curMin) {          // 发现一个比当前最小值更小的元素
                curMin = A[j];            // 更新当前最小值
                curMinPos = j;            // 同时更新最小值所在的位置
            }                             // if 结束
        }                                 // 内层 for 结束：curMinPos 是 A[i..n-1] 中最小元素的位置
        std::swap(A[i], A[curMinPos]);    // 把本轮最小值换到 A[i]，A[i] 就此归位
    }                                     // 外层 for 结束
}                                         // selectionSort 结束

int main() {                                                              // 用 PPT 的 16 元素实例验证
    int A[16] = {24, 17, 40, 28, 13, 14, 22, 32, 40, 21, 48, 4, 47, 8, 37, 18};  // PPT 第 57 页的输入数组
    selectionSort(A, 16);                                                 // n = 16，就地排序
    for (int k = 0; k < 16; ++k) {                                        // 逐个打印排序后的元素
        std::cout << A[k] << (k == 15 ? '\n' : ' ');                     // 空格分隔，末尾换行
    }                                                                     // for 结束
    return 0;                                                             // 输出 4 8 13 14 17 18 21 22 24 28 32 37 40 40 47 48
}                                                                         // main 结束

运行结果同样是 4 8 13 14 17 18 21 22 24 28 32 37 40 40 47 48：两种算法的输出规格相同，差别在过程。

cur_min 与 cur_min_pos 的示例解读

PPT 用同一份 16 元素输入演示伪代码的读法。把下标写成 1 起（A[1] = 24，A[2] = 17，…，A[16] = 18）：

内层循环与输入实例无关：第 i 轮必然比较 n − i 次，因此比较次数恒为 (n − 1) + (n − 2) + … + 1 = n(n − 1)/2 = 120 次（n = 16）。逐行计数求和（见第九节的完整表格）得：

T(n) = 2n2 + 3n − 4 = Θ(n2)

与插入排序的关键对比：实例是否影响运行

PPT 第 163～165 页强调“相同输入规模，实例影响运行”，但这句话只对插入排序成立：插入排序的比较次数依赖实例（数组升序时 n − 1 次，数组降序时 n(n − 1)/2 次）；而选择排序的内层循环 for j = i + 1 to A.length 与元素取值无关，无论输入是什么，比较次数都恒为 n(n − 1)/2（n = 16 时 120 次）。因此选择排序没有“最好情况”可言，它的最好、最坏、一般情况完全相同。

易错

两条结论不要记混：插入排序 T(n) = 3n2/2 + 7n/2 − 4，选择排序 T(n) = 2n2 + 3n − 4。系数不同（3/2 与 2）不影响渐近结论，两者的最高阶项都是 n2，所以都记作 Θ(n2)；但书写时要按逐行计数的结果把系数与低阶项写全，不要只写 n2。

八、算法分析的原则

要比较“哪个算法更快”，先得解决三个问题：机器不同怎么办？操作粒度不同怎么办？同一规模下输入不同怎么办？

原则一：分析必须独立于机器

机器的运算速度直接影响算法的运行时间，用两台不同的机器跑两个不同的算法，根本无法公平比较：

机器运算速度运行算法运行时间
天河三号百亿亿次 / 秒插入排序无法公平比较
个人电脑十亿次 / 秒选择排序

结论：分析算法的运行时间应独立于机器。于是我们把注意力从“秒”转向“做了多少次基本操作”。

原则二：归纳基本操作并统一机器性能

把算法中反复出现的动作归纳为基本操作：运算 + − × ÷，赋值 :=，比较 > < =。并假设每个基本操作的代价都是 1——这就是“统一机器性能”。

基本操作：+ − × ÷   |   := > < =   →   每个代价记为 1

统一机器性能之后，算法的运行时间就只依赖于问题输入规模 n 与具体的输入实例。

原则三：分析最坏情况

同样规模 n = 16，插入排序在不同实例上的比较次数可以差 8 倍：数组升序时只要 1 + 1 + … + 1 = n − 1 = 15 次；数组降序时却要 1 + 2 + … + (n − 1) = n(n − 1)/2 = 120 次。三种情况对比：

输入情况情况说明是否常用
最好情况不常出现，不具普遍性不作主要依据
最坏情况确定上界，更具一般性常用
一般情况情况复杂，分析难度大较少使用

因此课程常用最坏情况分析算法运行时间：它给出的是保证不会超出的上界。

结论

在“统一机器性能 + 分析最坏情况”的前提下，算法运行时间仅依赖于问题输入规模 n，表示为 T(n)。这正是后面所有复杂度公式的自变量。

十、渐近分析：Θ / O / Ω

渐近分析：分析 n 充分大时函数的大小关系，并用渐近记号表示。三个记号分别刻画“紧确界、上界、下界”：

渐近记号名称直观含义
T(n) = Θ(g(n))渐近紧确界增长速度和 g(n) 同阶，既能被它压住、也能压住它
T(n) = O(g(n))渐近上界增长不快于 g(n)
T(n) = Ω(g(n))渐近下界增长不慢于 g(n)

Θ 记号：渐近紧确界

Θ(g(n)) = { T(n) : ∃ c1, c2, n0 > 0，使得 ∀ n ≥ n0，c1g(n) ≤ T(n) ≤ c2g(n) }

图 3 Θ 记号（渐近紧确界）：存在 c1、c2、n0 > 0，使 ∀ n ≥ n0 有 c1g(n) ≤ T(n) ≤ c2g(n)。n0 竖线右侧，T(n) 被两条参考曲线夹在中间

验证实例（PPT 的 Θ 记号示例）

取 T(n) = 3n2/2 + 7n/2 − 4，令 n0 = 2，当 n ≥ n0 时：

下界：3n2/2 + 7n/2 − 4 ≥ 3n2/2 ≥ n2（因为 7n/2 − 4 ≥ 0）

上界：3n2/2 + 7n/2 − 4 ≤ 3n2/2 + 7n2/2 + n2 = 6n2（因为 7n/2 ≤ 7n2/2 且 −4 ≤ n2）

故存在 c1 = 1、c2 = 6、n0 = 2，使得 ∀ n ≥ n0 有 c1n2 ≤ T(n) ≤ c2n2，即 T(n) = Θ(n2)。

Θ 的其他示例：3n2/2 + 7n/2 − 10 = Θ(n2)；n3 − n2 + n = Θ(n3)。系数与低阶项怎么变，都不影响 Θ 的结论。

O 记号：渐近上界

O(g(n)) = { T(n) : ∃ c, n0 > 0，使得 ∀ n ≥ n0，0 ≤ T(n) ≤ cg(n) }

图 4 O 记号（渐近上界）：存在 c、n0 > 0，使 ∀ n ≥ n0 有 0 ≤ T(n) ≤ cg(n)

O 记号示例：

  • cos n = O(1)：因为 |cos n| ≤ 1，取 c = 1 即可，常数也是“上界”。
  • n2/2 − 12n = O(n2)：低阶项 −12n 不起决定作用。
  • log7n = log2n / log27 = O(log2n) = O(log n)：用对数换底公式 logxN = logyN / logyx，底数只是常数因子。
  • ∑i = 1..n 1/i = O(log n)（假设 n 是 2 的整数幂）：把 1 + 1/2 + 1/3 + … + 1/n 按 1、2、4、8、… 分组放大，得 1 + 2·(1/2) + 4·(1/4) + 8·(1/8) + … = 1 + 1 + 1 + …，共 log n 项，所以 ≤ log n + 1 = O(log n)。

Ω 记号：渐近下界

Ω(g(n)) = { T(n) : ∃ c, n0 > 0，使得 ∀ n ≥ n0，0 ≤ cg(n) ≤ T(n) }

图 5 Ω 记号（渐近下界）：存在 c、n0 > 0，使 ∀ n ≥ n0 有 0 ≤ cg(n) ≤ T(n)

Ω 记号示例：

  • n3 − 2n = Ω(n3)
  • n2 + n = Ω(n2)
  • 同样有 ∑i = 1..n 1/i = Ω(log n)：把 1 + 1/2 + (1/3 + 1/4) + (1/5 + … + 1/8) + … 按 1/2 分组缩小，得到 1 + 1/2 + 2·(1/4) + 4·(1/8) + … = 1 + (1/2)log n。

重要结论

T(n) = Θ(g(n)) 等价于 T(n) = Ω(g(n)) 且 T(n) = O(g(n))：能同时给出上界和下界，才叫紧确界。

算法运行时间称为算法的时间复杂度，通常使用渐近记号 O 表示（例如说“插入排序的时间复杂度是 O(n2)”）。

十一、本节小结

算法分析的原则与工具

三条原则

① 统一机器性能：归纳基本操作 + − × ÷ 与 := > < =，假设代价均为 1；
② 分析最坏情况：最好情况不常出现，最坏情况确定上界、更具一般性；
③ 采用渐近分析：忽略系数与低阶项，用 Θ / O / Ω 描述。

三件工具

① 逐行计数：数出每行伪代码执行多少次；
② 求和公式：1 + 2 + … + n = n(n + 1)/2 等；
③ 渐近记号：Θ 紧确界、O 上界、Ω 下界。

两个排序算法的最终判定

算法（最坏情况）O(n) 的部分O(n2) 的部分总时间结论
插入排序 第 1、2、3、7 行（每轮的固定开销，合计 4n − 3 = O(n)） 第 4、5、6 行（∑ 型求和，n2 量级） T(n) = 3n2/2 + 7n/2 − 4 Θ(n2)，即 O(n2)
选择排序 第 1、2、3、8 行（每轮的固定开销，合计 4n − 5 = O(n)） 第 4、5、6、7 行（∑ 型求和，n2 量级） T(n) = 2n2 + 3n − 4 Θ(n2)，即 O(n2)

两者的最高阶项都是 n2，所以都是平方级算法：当 n 从 16 增大到 1000 时，工作量从几百次涨到上百万次。

一页速记

算法 = 良定义步骤序列（有穷性 / 确定性 / 可行性）；表示 = 自然语言 + 编程语言 + 伪代码；分析 = 统一机器性能 + 最坏情况 + 渐近记号；插入排序 T(n) = 3n2/2 + 7n/2 − 4 = Θ(n2)，选择排序 T(n) = 2n2 + 3n − 4 = Θ(n2)；比较次数与总操作次数是两回事。

一、判断题

1. 给定计算问题，算法可以定义为一系列良定义的计算步骤。绪论 · 原卷 17

  • A. 对
  • B. 错

答案：对　这正是本节对算法的定义：给定计算问题，算法是一系列良定义（well-defined）的计算步骤，逐一执行这些步骤即可得到预期的输出。三个关键词缺一不可 —— 输入、计算步骤（每一步都明确无歧义、可机械执行）、输出；再配合后面讲的三条性质（有穷性、确定性、可行性），才算完整的算法。

2. 自然语言表示算法总是精确且不会产生歧义。绪论 · 原卷 18

  • A. 对
  • B. 错

答案：错　自然语言的优点是贴近人类思维、易于理解主旨，但缺点正是表述繁琐、容易产生歧义，还常用「……」这类不严谨描述。反例就是本节举的「交换两个数的位置」——没说明是哪两个数，因而不满足确定性；再如「将大元素放数组后部、小元素放数组前部」无法拆解为基本操作，因而不满足可行性。这正是需要伪代码的原因：用编程语言的形式骨架 + 接近自然语言的表达，兼顾「可读」与「无歧义」。
